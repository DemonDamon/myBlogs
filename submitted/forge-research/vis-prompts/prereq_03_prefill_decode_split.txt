[主题与布局设想]
一幅展示 Prefill 与 Decode 两阶段计算特征对比的信息图。画面分为左右两大区域，左侧是 Prefill 阶段，右侧是 Decode 阶段，中间用 KV Cache 传输箭头连接。每侧顶部是阶段名称，中部是核心操作的可视化，底部是关键指标面板。最底部有一个横向对比表格总结两者差异，以及"为什么要分离部署"的结论框。

[视觉模块详解]
顶部标题："Prefill vs Decode：两个截然不同的计算阶段"

左侧区域（标题"Prefill 阶段"，深蓝色主调）：
- 核心可视化：一个大的方阵代表完整的 Attention 矩阵 QK^T
  - 矩阵内部用深蓝渐变色填充，表示密集计算
  - 矩阵尺寸标注"L_prompt × L_prompt"
  - 矩阵旁标注"一次性处理全部 prompt Token"
- 下方图标区：
  - GPU 利用率仪表盘：指针指向 >90%，绿色区域
  - 标注"Compute-bound（计算密集型）"
  - FLOPs 公式："∝ L² × d"
- 关键标签："高并行度"、"大 batch"、"算术强度高"

中间连接区域：
- 粗箭头从左向右，标注"KV Cache 传输"
- 箭头上方标注传输数据量公式

右侧区域（标题"Decode 阶段"，绿色主调）：
- 核心可视化：一个极扁的长条代表单行向量 × 矩阵运算
  - 一个窄的绿色条（q_new，1×d）乘以一个高的灰色块（K_cache，t×d）
  - 标注"每步只生成 1 个 Token"
- 下方图标区：
  - 显存带宽仪表盘：指针指向 >80%，橙色区域
  - 标注"Memory-bound（访存密集型）"
  - FLOPs 公式："∝ (L_prompt + t) × d"
- 关键标签："串行依赖"、"低算力利用率"、"算术强度低"

底部对比表格（水平排列）：
| 指标 | Prefill | Decode |
| 瓶颈类型 | 计算（Compute） | 访存（Memory BW） |
| 并行度 | 高（全序列并行） | 低（逐 Token 串行） |
| 算术强度 | 高（数百~数万） | 低（~1） |
| GPU 利用率 | >90% | <30% |
| 最优硬件 | 高算力 GPU | 高带宽 GPU |

最底部结论框（橙色边框高亮）：
"混合部署时互相干扰 → Prefill/Decode 分离部署，各用最优硬件配置"

[风格与配色方案]
专业学术论文图表风格。Prefill 使用深蓝色系（#1565C0 主色，#E3F2FD 浅色背景）。Decode 使用绿色系（#2E7D32 主色，#E8F5E9 浅色背景）。KV Cache 传输箭头使用橙色（#FF6B35）。仪表盘使用对应阶段的颜色。对比表格使用交替行灰色背景。结论框使用亮橙色高亮边框。

[技术参数建议]
文字必须清晰可辨。保持文字与背景的高对比度。建议 16:9 比例。2K 分辨率。矢量图风格，扁平化设计，专业学术论文图表风格。
