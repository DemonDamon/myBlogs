## 概述

Claude Code刚刚在研究中预览版中推出了**智能体团队（Agent Teams）**功能。这不再是单个智能体顺序处理任务的老模式，而是一个主导智能体可以委派多个队友并行工作，研究、调试、构建，同时相互协调。

## 从单打独斗到团队作战

传统的AI编程助手就像个全能型独行侠，什么活都自己干。智能体团队模式则引入了真正的分工协作：

- **主导智能体**：担任项目经理，负责分解任务、分配工作、整合结果
- **多个队友**：各自拥有独立的环境窗口，可以同时处理不同任务

### 用户反馈

有网友在体验后表示，这正是之前缺失的一环：

> "一直在用skills和MCP构建模块化工作流，但智能体间的协调总是手动的。让主导智能体委派和合并结果，正是处理像'重构认证层'这类复杂任务时需要的。"

## 与子智能体的本质区别

很多人可能会问：这和子智能体有什么不同？关键在于**沟通方式**。

| 特性 | 子智能体 | 智能体团队 |
|------|---------|-----------|
| 上下文 | 独立环境窗口，结果返回主智能体 | 完全独立的环境窗口 |
| 通信 | 仅向主智能体报告 | 队友间直接消息传递 |
| 协调 | 主智能体管理所有工作 | 共享任务列表，自我协调 |
| 适用场景 | 只需结果的聚焦任务 | 需要讨论协作的复杂工作 |

### 关键差异

- **子智能体**：运行在单个会话中，只能向主智能体报告结果
- **智能体团队**：每个队友都是独立的Claude实例，可以直接相互通信，无需通过主导智能体中转

这就像是一个部门里的同事可以直接交流，而不是所有沟通都要经过经理。

## 两种显示模式，适应不同习惯

智能体团队支持两种显示模式：

### 1. 进程内模式（In-Process Mode）
- 所有队友都在主终端中运行
- 用 Shift+上下键选择队友直接对话
- 任何终端都能用
- **默认模式，无需额外设置**

### 2. 分割窗格模式（Split Pane Mode）
- 给每个队友独立的窗格
- 可以同时看到所有人的输出
- 需要 tmux 或 iTerm2 支持

### 技术门槛

有网友调侃道：
> "等不及看非开发人员学习tmux了。"

这话虽然带点讽刺，但确实点出了技术门槛问题——好在默认的进程内模式无需额外设置。

## 成本考量：更多令牌，更多价值

智能体团队模式确实会消耗更多令牌，**每个队友都是独立的Claude实例**。

但正如文档中指出的，对于研究、评审和新功能开发，额外的令牌成本通常是值得的。常规任务还是用单会话更经济。

## 实际应用场景

这种模式特别适合需要多角度并行探索的任务：

### 1. 并行代码审查
- 安全、性能、测试覆盖度由不同队友同时审查
- 每个队友专注一个维度
- 最后整合所有反馈

### 2. 竞争性假设调试
- 多个队友各自验证不同理论
- 通过辩论找出根本原因
- 类似于"魔鬼代言人"的方法

### 3. 跨层协调
- 前端、后端、测试由不同队友分别负责
- 各自处理自己的领域
- 通过直接通信协调接口和依赖

## 启用方法

智能体团队**默认关闭**，需要在 `settings.json` 中设置环境变量：

```json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

启用后，只需用自然语言告诉Claude创建智能体团队并描述任务结构即可。

## 当前限制

作为实验性功能，智能体团队还有一些限制：

1. 只有一个团队会话
2. 不能嵌套团队
3. 分割窗格需要特定终端支持

但对于需要真正协作的复杂编程任务，这已经迈出了重要一步。
